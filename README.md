# SBA 928 — Retail Market Research Resubmission

This Python project analyzes the supplied Online Retail dataset, evaluates local FLAN-T5 fine-tuning, and generates evidence-based market-research briefs.

The resubmission addresses instructor feedback about training-task diversity, baseline loading, quantitative bias/fairness auditing and reporting.

## Project Workflow

1. Inspect and clean the retailer data.
2. Calculate customer, product, country and monthly summaries.
3. Prepare diverse market-research training examples.
4. Fine-tune FLAN-T5 Small using separate training and validation scenarios.
5. Compare original and fine-tuned responses on reserved test scenarios.
6. Audit customer-warning decisions across geographic labels.
7. Generate verified briefs using Python calculations and fixed templates.

## Retail Data Rules

The positive-sales analysis:

- Removes extra exact duplicate rows, retaining one copy.
- Excludes cancelled invoices.
- Excludes nonpositive quantities and unit prices.
- Retains otherwise valid sales without CustomerIDs.
- Calculates positive sales revenue as Quantity × UnitPrice in GBP.
- Groups product demand by StockCode.
- Uses an available product description and labels missing descriptions.
- Counts distinct qualifying invoices for customer purchase frequency.

Customer-level calculations exclude missing CustomerIDs because those purchases cannot be assigned to identified individuals.

Product cancellation reviews report signed units separately from positive sales. Signed balances do not establish that every reversal has been matched to its original purchase.

Monthly comparisons exclude incomplete months and require consecutive complete periods. December 2011 is partial through December 9.


## Expanded Fine-Tuning Experiment

The v3 experiment covers five task families:

| Task Family | Training Examples | Validation Examples | Test Examples |
|---|---:|---:|---:|
| Consumer behavior | 128 | 32 | 32 |
| Country coverage | 128 | 32 | 32 |
| Market trends | 128 | 32 | 32 |
| Product demand | 128 | 32 | 32 |
| Competitor research | 128 | 32 | 32 |
| **Total** | **640** | **160** | **160** |

Each scenario has two prompt variations. The splits therefore contain 320 training, 80 validation and 80 test scenarios.

All v3 examples are explicitly synthetic. Several tasks include figures calculated by Python. The experiment measures reporting and interpretation of supplied evidence, not independent arithmetic ability.

Source groups and identical evidence are separated across splits. Templates and reasoning patterns remain shared. Dataset fingerprints are recorded in [the manifest](training_data_v3/manifest.json).

Recorded settings:

- Model: `google/flan-t5-small`
- Revision: `0fc9ddf78a1e988dac52e2dac162b0ede4fd74ab`
- Transformers: `4.57.6`
- Six epochs; batch size four
- Learning rate: `0.00005`
- Seed: `928`
- 960 optimizer updates
- Selected checkpoint: epoch 6

Validation loss decreased from 3.468904 to 0.020701.

The fine-tuned model matched 132/160 reference responses exactly after whitespace normalization: **82.5% strict reference agreement**. Both prompt variations matched in 64/80 scenarios.

The original model had no strict reference matches and 12 empty responses. Zero strict matches must not be interpreted as zero factual accuracy.

Manual review found remaining customer-warning and monthly-trend errors. The model requires verification before business use.

## Quantitative Audit and Mitigation

A controlled regression audit varied four geographic labels and four customer counts.

| Method | Correct Warning Decisions |
|---|---:|
| Original model | 8/16 |
| Fine-tuned v3 model | 8/16 |
| Python safeguard | 16/16 |

Both models missed every required warning. Label-level accuracy gaps were zero, reflecting equal measured performance rather than proof of population fairness.

The application applies the explicit warning rule in Python:

```python
identified_customers < 5
```

Its safeguard performance is reported separately from model performance.

## Business Limitations

The retailer data does not establish national market demand, purchasing motives, competitor performance or market share.

Inventory recommendations require stock levels, supplier lead times and other operational information before exact reorder quantities can be determined. Recorded sales do not capture demand lost through stockouts.

Synthetic evaluation results do not establish reliability on real retail briefs or new prompt formats.
